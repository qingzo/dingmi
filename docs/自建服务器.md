# 自建同步服务器

> 第 1–9 节是宝塔面板（Ubuntu 24.04）的做法；不用宝塔、自己管 Linux 服务器的看第 10 节；备份每天拷一份到别处、连不上时通知你（可选）看第 11 节。服务端只有一个可执行文件，不需要 MySQL，也不用装任何运行环境。
>
> 自建服务器能用叮咪的全部同步功能（电脑同步、手机网页、命令行管理、每天备份）。照着文档能装好；出了问题可以反馈，有空会回，不保证答疑。
>
> 每条命令的完整说明：`dingmi-server help`。

下面的 `<服务器IP>` 换成你服务器的公网 IP。

## 0. 准备

- 程序文件 `dingmi-server`：用编好的，或者自己编。普通服务器用 x86_64，ARM 服务器（树莓派这类）用 arm64（arm64 版能编出来，但还没在 ARM 机器上真跑过，遇到问题欢迎反馈）。自己编：
  - 在开发电脑上 `cargo zigbuild --profile server --target x86_64-unknown-linux-musl -p dingmi-server`，产物在 `target/x86_64-unknown-linux-musl/server/`；arm64 把两处 `x86_64` 换成 `aarch64`（先 `rustup target add aarch64-unknown-linux-musl`）。
  - Windows 上第一次编译要先装：`rustup target add x86_64-unknown-linux-musl`、`pip install --user ziglang`、`cargo install cargo-zigbuild --locked`。
  - cargo-zigbuild 找不到 zig 时，指定一下路径：`CARGO_ZIGBUILD_ZIG_PATH=<Python 用户目录>\site-packages\ziglang\zig.exe`。
  - 改过手机网页（`apps/mobile/`）的话，先 `npm run build:mobile` 再编译服务器。
- 程序只用一个端口：**7788（TCP）**。叮咪电脑端、手机网页、下载根证书都走它。

## 1. 端口：云厂商安全组

在云服务器控制台的「安全组 / 防火墙」里，最后只留这两条入方向规则：

| 端口 | 来源 | 用途 |
| --- | --- | --- |
| TCP 7788 | `0.0.0.0/0`（所有人） | dingmi |
| 宝塔面板端口 | **只填你自己的 IP**（百度搜"IP"能看到） | 管理宝塔 |

- **22（SSH）关掉**。宝塔的网页终端是在服务器内部连本机的，外面关了不影响它；万一宝塔也进不去，还能用云控制台的「远程连接（VNC）」。
- 宝塔默认放行的 80、443、888、21、3306、39000-40000 等，用不到就都删掉。
- 家里宽带的 IP 会变，宝塔打不开时先看看是不是 IP 变了，到安全组里改一下来源。

## 2. 端口：宝塔防火墙

宝塔 →「安全」→「系统防火墙」：**添加端口规则 7788，TCP，放行**。

两层防火墙是叠加的，任何一层没放行都连不上。宝塔防火墙里的 22 可以留着（外面已经被安全组挡住了）。

## 3. 上传程序

宝塔 →「文件」：

1. 进到 `/www/wwwroot`，新建文件夹 `dingmi`。
2. 进入 `/www/wwwroot/dingmi`，上传 `dingmi-server`。

程序放在网站目录下没关系；数据（密钥、证书、数据库）默认放在 `/var/lib/dingmi`，在网站目录之外，不会被当成网页文件下载到。

## 4. 初始化

宝塔 →「终端」，执行（`<服务器IP>` 换成真实 IP）：

```bash
chmod 755 /www/wwwroot/dingmi/dingmi-server
/www/wwwroot/dingmi/dingmi-server init --ip <服务器IP>
```

会生成服务器密钥、根证书和数据库，放在 `/var/lib/dingmi`。

端口默认是 7788，下面都按 7788 写。想换一个（比如 7788 被别的程序占了）：`init --ip <服务器IP> --port 8899`，后面放行端口、反向代理里的 7788 都换成你的端口。

想在任何目录直接输 `dingmi-server` 就能用，再执行一次（以后更新程序只换原文件，这个不用动）：

```bash
ln -s /www/wwwroot/dingmi/dingmi-server /usr/local/bin/dingmi-server
```

最后会输出 **根证书指纹（SHA-256）**，记下来，以后在 iPhone 上安装证书时核对。

## 5. 启动：宝塔 Go 项目

dingmi-server 是一个独立的可执行程序（Rust 写的，不需要任何运行环境），宝塔里按「Go 项目」添加就行：「网站」→「Go 项目」→「添加 Go 项目」（不同版本的宝塔叫法可能稍有不同）。

| 项 | 填写 |
| --- | --- |
| 项目执行文件 | `/www/wwwroot/dingmi/dingmi-server` |
| 项目名称 | `dingmi` |
| 项目端口 | `7788`（有「放行端口」就勾上） |
| 执行命令 | `/www/wwwroot/dingmi/dingmi-server run` |
| 运行用户 | `root` |
| 开机启动 | 勾上 |
| 绑定域名 | 留空 |

**不要开「外网映射」或反向代理。** 7788 上跑的是叮咪自己的加密协议和自签证书的 HTTPS，手机和电脑必须直接连到程序本身；中间经过 Nginx 的话，电脑端连不上，手机也会拿到错误的证书。

保存后状态应该是「运行中」，项目日志里能看到：`dingmi-server 0.4.0 启动了，在 7788 端口等待连接`。

宝塔里没有 Go 项目的话，用「软件商店」里的「进程守护管理器」也行：启动用户 `root`，运行目录 `/www/wwwroot/dingmi`，启动命令同上，进程数量 `1`。

## 6. 检查

- **端口通没通**：在自己电脑的浏览器打开 `http://<服务器IP>:7788/ca`，会下载一个 `dingmi-ca.mobileconfig` 文件，说明端口和程序都正常。这个文件下载到电脑上没有用，删掉就行。
- **iPhone（可以现在做，也可以等手机收件箱做好再做）**：
  1. 用 Safari 打开 `http://<服务器IP>:7788/ca` →「允许」下载描述文件。
  2. 打开「设置」，最上面会出现「已下载描述文件」→ 安装。安装前可以点进证书看「更多详细信息」，核对 SHA-256 指纹和第 4 步记下的一致。
  3. 「设置 → 通用 → 关于本机 → 证书信任设置」→ 打开「叮咪私有根证书」。
  4. Safari 打开 `https://<服务器IP>:7788/m/`，能打开「发到叮咪」页面（没有证书警告）就说明手机已经信任了你的服务器。这时页面会提示「要从电脑上的叮咪打开」，是正常的，真正的入口在电脑上添加手机时给出。

**安卓**：用 Chrome 打开 `http://<服务器IP>:7788/ca.crt` 下载证书，再到「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」，选刚下载的 `dingmi-ca.crt`（不同手机菜单位置不一样，可以在设置里搜「CA 证书」）。

**绑了域名的手机不用装证书**（第 8 节）：手机网页走域名，用的是宝塔申请的正规证书，这一节可以跳过。

### 换成只认这台服务器的根证书（可选）

`init` 生成的根证书能给任何网站签证书：`ca.key.pem` 万一泄露（服务器被人拿下、备份传到了不该去的地方），别人就能用它冒充别的网站骗装了证书的手机。可以换一张带「名称约束」的根证书，只能给这台服务器的 IP 签：

```bash
# 先在 Go 项目里停止 dingmi（systemd：systemctl stop dingmi）
/www/wwwroot/dingmi/dingmi-server ca --new          # 先看说明
/www/wwwroot/dingmi/dingmi-server ca --new --yes    # 换
# 再启动 dingmi
```

- 旧的 `ca.crt.pem`、`ca.key.pem` 改名留着（后面加 `.旧-<时间>`），不会删。
- 换了以后，**用 IP 打开手机网页的手机都要重装一次证书**：iPhone 先在「设置 → 通用 → VPN 与设备管理」里删掉旧的描述文件，再照上面第 1–3 步装新的（核对 `ca` 命令显示的新指纹）；安卓重新下载 `ca.crt` 安装。绑了域名的手机不受影响。
- 以后服务器换了 IP，这张根证书不认新 IP（`init --ip <新IP>` 时会提醒），要再执行一次 `ca --new --yes`、手机再重装。不带约束的根证书换 IP 不用重装，这是两者的取舍。
- `dingmi-server ca` 能看到现在这张有没有约束、只认哪个 IP。
- 已经装好的旧根证书不受影响：不执行这条，什么都不变。

## 7. 配对码

配对码是一行 `dingmi://...`，只能用一次。每台电脑用一个。

- **第二台及以后的电脑**：不用登录服务器。在已经同步的电脑上打开「设置 → 同步 → 再加一台电脑」，点「生成配对码」，复制到新电脑上，输同步密码。这个配对码带着空间密钥，24 小时内有效。
- **第一台电脑**，或者手边没有已经同步的电脑：在终端执行下面的命令，配对码 24 小时内有效。第一台电脑设好同步密码后，叮咪会显示一个**恢复码**，一定要存好。

```bash
/www/wwwroot/dingmi/dingmi-server invite
```

服务器上没有空间密钥，所以空间已经在用以后，服务器上生成的配对码不带它：新电脑粘贴后要输恢复码（不用同步密码）。

## 8. 手机网页绑域名（可选）

有域名的话，可以给手机网页绑上，证书交给宝塔申请。绑好以后 iPhone 不用再装描述文件，安卓的分享菜单也能用；**电脑也会先走这个域名**（`wss://域名/sync`，下面配置里的 `/sync` 那一段）：只放行 443 的公司网络也能同步，以后服务器换了 IP 只要改域名解析，电脑不用重新配对。走不通时电脑自己退回 `<服务器IP>:7788`，所以 7788 端口还是要一直放行（没绑域名的、旧版本的叮咪都靠它）。服务器在国内的话，域名要先备案；香港、海外的不用。

1. **域名解析**：在域名服务商那里加一条 A 记录，比如 `sync.example.com` 指到 `<服务器IP>`。
2. **建站点**：宝塔「网站」→「添加站点」，域名填 `sync.example.com`，PHP 选「纯静态」，不建数据库、不建 FTP。
3. **申请证书**：打开这个站点的「SSL」→「Let's Encrypt」→ 申请，好了以后打开「强制 HTTPS」。证书宝塔会自动续。
4. **反向代理**：站点的「反向代理」→「添加反向代理」：目标 URL 填 `https://127.0.0.1:7788`（**一定是 https**，宝塔默认给的是 http；写成 http 的话打开网页会提示「请用 https:// 打开」），发送域名填 `$host`，**不要开缓存**。
5. **改一下配置**：点这条反向代理的「配置文件」，把 `location` 那一段整个换成下面这样；再打开站点的「配置文件」，在 `server {` 下面加一行 `client_max_body_size 60m;`（手机一次能发 50 MB，Nginx 默认只放 1 MB，不加的话发大图片、大文件会失败）。

   ```nginx
   location / {
       proxy_pass https://127.0.0.1:7788;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_http_version 1.1;
       proxy_ssl_verify off;
       proxy_read_timeout 120s;
   }
   # 电脑的同步连接（WebSocket），一连就是很久，所以超时放长
   location = /sync {
       proxy_pass https://127.0.0.1:7788;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection "upgrade";
       proxy_ssl_verify off;
       proxy_read_timeout 1d;
       proxy_send_timeout 1d;
   }
   ```

   - `proxy_ssl_verify off`：叮咪在服务器里面用的是自签证书，让 Nginx 不核对它；手机看到的还是宝塔申请的正规证书。
   - `/sync` 那一段：`Upgrade`、`Connection` 两行让 Nginx 转 WebSocket；没有这一段电脑也能同步，只是一直直连 7788。
   - `X-Real-IP` 这两行一定要有：叮咪靠它认出每部手机的真实 IP，没有的话所有手机都算成同一个，一部手机输错几次令牌，所有手机都会被屏蔽 10 分钟。
6. **检查**：浏览器打开 `https://sync.example.com/m/`，能看到叮咪的页面（提示「要从电脑上的叮咪打开」是正常的）、地址栏没有证书警告，就对了。
7. **告诉叮咪**：终端执行

   ```bash
   /www/wwwroot/dingmi/dingmi-server web https://sync.example.com
   ```

   不用重启。之后在电脑上「设置 → 同步 → 手机」添加的手机就用这个网址，不再显示「装证书」那一步。已经添加过的手机还是原来的网址，想换就作废、重新添加。

取消：`dingmi-server web --off`；看现在是哪个：`dingmi-server web`。

**用 Cloudflare 管域名的**：这条记录设成「仅 DNS」（灰色云朵）。开了代理（橙色云朵）的话，Nginx 看到的都是 Cloudflare 的 IP，要在配置里改成从 `CF-Connecting-IP` 取真实 IP（`real_ip_header CF-Connecting-IP;` 加上 Cloudflare 的 IP 段 `set_real_ip_from`），不然所有手机都算成那几个 IP。电脑走域名时也会经过 Cloudflare（它能转 WebSocket），真实 IP 同样要从 `CF-Connecting-IP` 取；走不通时退回直连 `IP:7788`，那条不经过 Cloudflare。

## 9. 搬家和恢复

### 数据目录里有什么

`/var/lib/dingmi`：

| 文件 | 是什么 | 丢了会怎样 |
| --- | --- | --- |
| `dingmi-server.db` | 同步数据库：密文的提醒和笔记、电脑和手机的登记、服务器的通信密钥 | 最要紧。每天自动备份到 `backups/` |
| `files/` | 附件（图片、文件，都是密文） | 不在每天的备份里。丢了也不怕：恢复以后电脑会把本机的附件重新传上来 |
| `inbox/` | 手机发来、电脑还没取走的（密文）。电脑取走就删；超过 30 天一直没取走的，每天收尾时删掉 | 丢了的那几条电脑就取不到了 |
| `ca.key.pem`、`ca.crt.pem` | 自签根证书 | 只影响用 IP 打开手机网页的手机（要重装证书）；绑了域名的不受影响 |
| `backups/` | 每天的备份，默认留 14 天 | |

**这些都在同一台服务器上**：服务器整个坏了，`backups/` 也跟着没了。所以隔一段时间在宝塔「文件」里把 `backups/` 里最新的一份、`ca.key.pem`、`ca.crt.pem` 下载到自己电脑上（这几样不大）。里面有服务器的通信密钥和根证书私钥，**不要发给别人**。想每天自动拷一份到别处，见第 11 节。

### 搬到新服务器（旧的还能登录）

1. 旧服务器：宝塔「Go 项目」里**停止** dingmi，把整个 `/var/lib/dingmi` 压缩下载（附件多的话会比较大）。
2. 新服务器：照第 1–3 节放行端口、上传程序；把压缩包解压到 `/var/lib/dingmi`（不要执行 `init` 生成新的密钥）。
3. IP 变了的话执行 `/www/wwwroot/dingmi/dingmi-server init --ip <新IP>`（密钥和数据不变），绑了域名的把域名解析改到新 IP。
4. 照第 5 节启动。电脑端：IP 没变、或者绑了域名的什么都不用改；IP 变了的要在「设置 → 同步」里改服务器地址。

### 拿备份恢复（数据库坏了、误操作、服务器整个丢了）

1. 宝塔「Go 项目」里**停止** dingmi。
2. 服务器整个丢了：先照「搬到新服务器」装好程序，把下载下来的 `ca.key.pem`、`ca.crt.pem`、备份文件放进 `/var/lib/dingmi/backups/`（根证书两个文件放在 `/var/lib/dingmi/`），执行 `/www/wwwroot/dingmi/dingmi-server init --ip <IP>`。
3. `/www/wwwroot/dingmi/dingmi-server backups` 看有哪些，`/www/wwwroot/dingmi/dingmi-server restore-backup <日期>` 恢复。原来的数据库会改名留着（`dingmi-server.db.恢复前-<时间>`），不会删。备份里记的是当时的 IP：换了服务器、IP 变了的话，恢复完再执行一次 `/www/wwwroot/dingmi/dingmi-server init --ip <新IP>`。
4. 启动。电脑和手机连上时会发现服务器「回到了以前」，自己从头同步，把本机的东西（**含附件**）重新传一遍：备份之后新加的、附件就都回来了。每台电脑都要打开一次叮咪才会传它那份。

**恢复以后要知道的**（备份里没有的东西，服务器也就不认识了）：

- **备份之后才配对的电脑**会提示「服务器不再接受这台电脑……需要重新配对」：在别的电脑上生成配对码，或者用恢复码重新配对，本机的数据会合进去。备份之后才建的空间整个没了：给它生成一个新空间的配对码（`invite --new-space`），重新配对。
- **备份之后才添加的手机**打开时会提示「这部手机已经不能用了」：在电脑上重新添加。
- **备份之后改过同步密码或恢复码的**：已经同步的电脑、手机照常用；新加的设备要输**改之前**的密码、恢复码。在任意一台电脑上再改一次同步密码（和恢复码）就对上了。
- 自动重传要电脑上的叮咪是 0.4 及以后的版本（旧版不认「服务器回到了以前」）。
- 改名留着的旧数据库（`dingmi-server.db.恢复前-<时间>`）和备份一样，过了「备份留几天」自动删掉。

## 10. 不用宝塔（systemd）

适用于 Ubuntu、Debian 这类用 systemd 的 Linux。下面的命令都用 root 或者加 `sudo` 执行；安全组照第 1 节只放行 7788。

### 装上

```bash
# 程序放到 /usr/local/bin（文件名下载下来是什么就写什么）
install -m 755 dingmi-server /usr/local/bin/dingmi-server

# 专用用户：程序哪天出了漏洞，对方也只碰得到 /var/lib/dingmi
useradd --system --no-create-home --shell /usr/sbin/nologin dingmi

# 初始化（<服务器IP> 换成公网 IP），数据在 /var/lib/dingmi，交给 dingmi 用户
dingmi-server init --ip <服务器IP>
chown -R dingmi:dingmi /var/lib/dingmi

# 系统自带防火墙开着的话放行 7788（ufw 举例）
ufw allow 7788/tcp
```

`init` 最后输出的根证书指纹记下来（第 6 节 iPhone 装证书时核对）。

### 开机自启

新建 `/etc/systemd/system/dingmi.service`：

```ini
[Unit]
Description=dingmi-server
After=network-online.target
Wants=network-online.target

[Service]
User=dingmi
Group=dingmi
ExecStart=/usr/local/bin/dingmi-server run
Restart=on-failure
RestartSec=3
# 每台电脑一直连着，连接数上限要够大
LimitNOFILE=65535
# 只让它写数据目录
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ReadWritePaths=/var/lib/dingmi

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now dingmi
systemctl status dingmi        # 应该是 active (running)
journalctl -u dingmi -f        # 看日志：「dingmi-server 0.4.0 启动了，在 7788 端口等待连接」
```

然后照第 6 节检查、第 7 节生成配对码。

### 平时的命令要用 dingmi 用户执行

第 7 节、第 9 节和下面「日常」里的命令，都在前面加 `sudo -u dingmi`，比如：

```bash
sudo -u dingmi dingmi-server invite
sudo -u dingmi dingmi-server spaces
```

**不要直接用 root 执行**：root 执行时新建的文件（数据库的临时文件、备份）属于 root，服务读写不了，会出错。已经这样了的话：`chown -R dingmi:dingmi /var/lib/dingmi`，再 `systemctl restart dingmi`。

| 要做的事 | 怎么做 |
| --- | --- |
| 看日志 | `journalctl -u dingmi -f` |
| 更新程序 | `systemctl stop dingmi` → `install -m 755 <新的 dingmi-server> /usr/local/bin/dingmi-server` → `systemctl start dingmi` |
| 重启（改了 IP 以后） | `systemctl restart dingmi` |
| 搬家、拿备份恢复 | 照第 9 节，「在 Go 项目里停止 / 启动」换成 `systemctl stop dingmi` / `systemctl start dingmi`，命令加 `sudo -u dingmi`；拷进来的文件最后 `chown -R dingmi:dingmi /var/lib/dingmi` |

### 手机网页绑域名（可选）

和第 8 节一样，只是反向代理自己配（电脑走域名的 `/sync` 那一段也要有）。配好以后执行 `sudo -u dingmi dingmi-server web https://sync.example.com`。

**Nginx**（证书用 certbot 之类自己申请）：

```nginx
server {
    listen 443 ssl;
    server_name sync.example.com;
    ssl_certificate     /etc/letsencrypt/live/sync.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/sync.example.com/privkey.pem;
    client_max_body_size 60m;

    location / {
        proxy_pass https://127.0.0.1:7788;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_ssl_verify off;
        proxy_read_timeout 120s;
    }
    location = /sync {
        proxy_pass https://127.0.0.1:7788;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_ssl_verify off;
        proxy_read_timeout 1d;
        proxy_send_timeout 1d;
    }
}
```

**Caddy**（自己申请、续证书）：

```caddy
sync.example.com {
    request_body {
        max_size 60MB
    }
    reverse_proxy https://127.0.0.1:7788 {
        header_up X-Real-IP {remote_host}
        transport http {
            tls_insecure_skip_verify
        }
    }
}
```

要点和第 8 节一样：目标是 **https**；`X-Real-IP` 一定要带（不然所有手机算成同一个 IP）；上传放到 60 MB；不核对叮咪自己的自签证书（手机看到的是 Nginx、Caddy 的正规证书）。

## 11. 异地备份和看着它（可选）

开源的 dingmi-server 只管同步本身：每天把数据库备份到 `backups/`（第 9 节），不往外发告警、不往别处传备份。
这些用你自己顺手的工具就行，比如：

- **每天拷一份到别处**：宝塔「计划任务」加一个每天跑的 Shell 脚本（不用宝塔的用 cron：`crontab -e` 加一行 `30 4 * * * <脚本>`），用 [rclone](https://rclone.org/) 把 `/var/lib/dingmi/backups/`、`ca.key.pem`、`ca.crt.pem`（想连附件一起的话再加 `files/`）同步到网盘或者对象存储。比如先 `rclone config` 配好一个叫 `remote` 的存储，脚本里写：

  ```bash
  rclone copy /var/lib/dingmi/backups remote:dingmi/backups
  rclone copy /var/lib/dingmi remote:dingmi --include "ca.*.pem"
  ```

  数据库备份里有服务器的通信密钥，**存的地方不能公开**。服务器整个丢了的时候，照第 9 节「拿备份恢复」，把拷出去的放回来就行。
- **连不上时通知你**：UptimeRobot 这类免费的外部监控加一条 `https://<你的域名>/m/`（绑了域名的）或者 `<服务器IP>:7788` 的端口检查；宝塔自带的「监控」也能看磁盘、内存。

## 日常

| 要做的事 | 怎么做 |
| --- | --- |
| 看日志 | Go 项目 → dingmi →「日志」 |
| 更新程序 | Go 项目里「停止」→ 在「文件」里上传新的 `dingmi-server` 覆盖，终端执行 `chmod 755 /www/wwwroot/dingmi/dingmi-server` →「启动」 |
| 看有哪些空间 | `/www/wwwroot/dingmi/dingmi-server spaces`：备注名、几台电脑几部手机、占了多少、最后活动 |
| 看有哪些电脑和手机 | `/www/wwwroot/dingmi/dingmi-server devices`，只看一个空间：`devices <空间>` |
| 作废一台电脑或一部手机 | `/www/wwwroot/dingmi/dingmi-server revoke <名字>`；同名的有好几台时写编号前几位（`devices` 里能看到）。正在连着的下一次同步就断开 |
| 给空间起备注名 | `/www/wwwroot/dingmi/dingmi-server note <空间> 爸妈`；去掉：`note <空间> --off` |
| 设容量上限 | `/www/wwwroot/dingmi/dingmi-server quota <空间> 2G`；不限：`quota <空间> off`。满了电脑推不上新东西，电脑上会提示「空间满了」，已经存着的不会删 |
| 停用一个空间 | `/www/wwwroot/dingmi/dingmi-server disable <空间> --yes`：这个空间的电脑和手机都连不上，30 天后连数据一起删掉；之前 `restore <空间>` 能恢复 |
| 给某个空间生成配对码 | `/www/wwwroot/dingmi/dingmi-server invite --space <空间>`；新建一个空间：`invite --new-space` |
| 看每天的备份 | `/www/wwwroot/dingmi/dingmi-server backups` |
| 改备份留几天、停用的空间几天后删、新空间默认多大 | `/www/wwwroot/dingmi/dingmi-server config backup-days 30`；`delete-days`、`default-quota`（比如 `1G`，`off` 不限，只管以后新建的空间）同样写法。只写 `config` 是看现在的 |
| 服务器换了 IP | `/www/wwwroot/dingmi/dingmi-server init --ip <新IP>`，再重启。密钥和数据不变，iPhone 上的根证书也不用重装（它只认根证书；换成了只认这台服务器的根证书的除外，见第 6 节）；电脑端要改一下服务器地址 |
| 查看根证书指纹 | `/www/wwwroot/dingmi/dingmi-server ca` |
| 看版本 | `/www/wwwroot/dingmi/dingmi-server version`（写着「开源版」） |

上面的 `<空间>` 写备注名，或者编号前几位（至少 4 位，`spaces` 里能看到）。不用宝塔的照第 10 节，命令前面加 `sudo -u dingmi`。

**备份**：程序每天自动把数据库备份到 `/var/lib/dingmi/backups/`，保留 14 天（`config backup-days` 能改）。建议偶尔在宝塔「文件」里把整个 `/var/lib/dingmi` 压缩下载一份。这个目录里有服务器密钥和根证书私钥，**不要发给别人**；丢了它，所有电脑和手机都要重新配对、重新装证书。

**日志时间**：日志用服务器的系统时区。如果时间比北京时间慢 8 小时，在终端执行 `timedatectl set-timezone Asia/Shanghai`，再重启 dingmi-server。

## 宝塔本身的安全

宝塔是这台服务器上最大的风险点，装好后：

- 「面板设置」里修改默认端口和安全入口，开启「BasicAuth」或「动态口令（两步验证）」。
- 面板保持最新版。
- root 密码改成足够长的随机密码（SSH 已经从外面关掉了，这一步是双保险）。

**可选的加固**：dingmi-server 现在用 root 运行。想多一层保险，可以给它建一个专用用户，这样即使程序哪天出了漏洞，对方也只能碰到 `/var/lib/dingmi`，碰不到整台服务器：

```bash
useradd --system --no-create-home --shell /usr/sbin/nologin dingmi
chown -R dingmi:dingmi /var/lib/dingmi
```

然后在 Go 项目里把运行用户改成 `dingmi` 再重启；以后在终端执行命令时前面加 `sudo -u dingmi`。
